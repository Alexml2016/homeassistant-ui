# Lighting Manager — план тестирования

## Автоматические проверки

Запуск с Python 3.13 (без зависимостей HA):

```bash
python -m unittest discover -s tests -v
python -m compileall -q custom_components/lighting_manager
```

`tests/test_lighting_manager_models.py` проверяет начало/конец вечернего интервала, пропуск после 23:00, окно ночного движения, задержку выключения, OR/max яркости, дни недели/продолжительность и некорректные правила.

## Проверка на Home Assistant OS (вручную)

**Внимание:** тестируйте сначала на отдельном светильнике/виртуальном `light`. Проверка требует установки интеграции и может переключать физическую нагрузку.

1. Развернуть ветку `feature/lighting-manager` через `deploy.sh`, перезапустить Core, добавить интеграцию и Lovelace-карточку.
2. Без правил проверить, что интеграция **не переключает** устройства.
3. Добавить правило LM-001 с `start` на время +2 минуты и `end` ещё через 2 минуты: проверить ON, затем OFF.
4. Создать второе перекрывающееся правило с большей яркостью: проверить увеличение до max и возврат после его завершения.
5. Создать ночное движение LM-002 с `active_period` на ближайший интервал: переключить бинарный датчик `on/off`; проверить `pending_off`, выключение после delay.
6. В активном правиле вручную изменить состояние/яркость в HA: убедиться, что автоматика не возвращает его немедленно; дождаться изменения активного набора правил.
7. В панели выбрать устройство, установить удержание на 5 минут, изменить его состояние и проверить, что автоматизация возобновится по таймеру либо ближайшему событию (что раньше).
8. Проверить выключение недиммируемого `light` и явно выбранного `switch` без ошибок параметров яркости/перехода.
9. Перезапустить Core посреди активного интервала: проверить восстановление правил, пересчёт датчиков и состояние ручной блокировки.
10. Проверить права: неадминистратор не должен управлять правилами через WebSocket.
11. Проверить логи Home Assistant на ошибки интеграции при недоступном устройстве, отсутствии солнечного события и переходе через полночь.

## Проверка обновления состояний (регрессия v0.1.1)

1. Создать двухминутное правило и оставить карточку открытой, не нажимая «Обновить».
2. Убедиться, что `inactive → active → inactive` появляется автоматически после наступления времени включения и выключения (сервер оценивает расписание примерно каждые 10 с).
3. Во время работы таймера выбрать правило, начать редактировать JSON и проверить, что текст и курсор редактора не сбрасываются при обновлениях статусов.
4. Вручную переключить управляемый светильник; убедиться, что обозначение ручного режима обновилось автоматически.
5. Убедиться, что после ухода с панели и возврата карточка снова получает обновления без дублирования подписок.
6. Тест без браузера: `node --test tests/test_lighting_manager_panel.js`.

## Визуальный интерфейс v0.2.0

1. На панели отображаются реальные `light.*`; `switch.*` не появляются в списке, пока не выбраны явно или не включены в существующие правила.
2. Выберите имеющийся светильник с ранее сохранённым LM-001; убедитесь, что его настройки заката, смещения, времени и яркости перенесены в поля формы.
3. Измените одно поле и нажмите «Сохранить правило»; сервер должен вернуть обновлённое правило без потери ID и остальных целей.
4. Добавьте второе правило по движению, выберите `binary_sensor.*` и проверьте задержку выключения и активное окно времени.
5. Проверьте дни недели, начало по фиксированному времени, завершение по длительности и переход через полночь.
6. Включите/выключите управляемую лампу кнопкой питания карточки; убедитесь, что при активном расписании установлен ручной приоритет.
7. Проверьте выбор и ручное добавление `switch.*`, отсутствие управления яркостью для обычного переключателя.
8. Проверьте, что фоновые обновления статусов не удаляют несохранённые данные в визуальных полях и в расширенном JSON.
9. Проверьте работу в мобильной ширине и тёмной теме; Clock и Garage должны остаться работоспособны.
10. Проверки JS: `node --check www/homeassistant-ui/panels/lighting-manager/lighting-manager.js` и `node --test tests/test_lighting_manager_panel.js`.

## Испытание визуального интерфейса v0.2

1. В панели выбрать несколько `light.*`, проверить реальные названия и состояния.
2. Поиск устройства должен фильтровать список. Опция «Только с правилами» должна скрывать остальные устройства.
3. Добавить `switch.*` явно через выпадающий список, проверить управление только выбранным переключателем.
4. Создать правило «закат +10 мин → 23:00» через форму и сохранить; проверить API, отображение и сохранение существующих правил.
5. Создать второе правило для того же света: проверить независимый выбор, редактирование, удаление и арбитраж яркости.
6. Переключить режим «По движению», выбрать `binary_sensor.*`, задать период и задержку; проверить в Home Assistant.
7. Проверить переход через полночь, дни недели, яркость и `transition`.
8. Создать правило, которое обслуживает несколько целей; форма должна предупреждать о связанных устройствах.
9. Начать редактировать и дождаться изменения статуса от сервера: введённые изменения не должны пропадать.
10. Проверить сохранение и откат изменения JSON в «Расширенных настройках».
11. Проверить отображение в светлой/тёмной теме и на мобильном экране.
12. Убедиться, что панели Clock и Garage по-прежнему работают.

## Критерии готовности к объединению с main

- CI: unit-тесты модели и компиляция Python — зелёные.
- Натурные тесты LM-001–LM-005 проходят; нет повторных собственных ручных блокировок.
- Установленная интеграция успешно переживает перезапуск, не изменяет сторонние сущности.
- Clock и Garage остаются без изменений.
- Документация соответствует проверенному способу развёртывания.

На 2026-10-11 эти натурные проверки ещё **не выполнены**.
