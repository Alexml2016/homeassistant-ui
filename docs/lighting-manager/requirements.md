# Lighting Manager — техническое задание v0.6

Дата: 2026-10-11. Цель — интеграция Home Assistant для независимых правил автоматического освещения и приоритетного ручного управления.

## 1. Объекты
- Обнаруживать `light.*` для выбора. `switch.*` подключать только по явному выбору; не изменять случайные реле.
- Для движения использовать `binary_sensor.*`.
- У одного устройства может быть несколько правил; одно правило управляет несколькими устройствами.

## 2. Правила
- Начало: фиксированное `HH:MM`, `sunrise` или `sunset` с offset в минутах; также начало при `motion`.
- Завершение: фиксированное время, событие солнца, продолжительность в секундах; для движения — `no_motion` с задержкой.
- Дни недели (ISO 1=пн … 7=вс), временные интервалы, пересекающие полночь. Для переноса конца на следующий день обязательно `end_day: next`.
- Для интервала в тот же день (`end_day: same`) цикл пропускается, если начало наступило не раньше конца.
- Яркость правила 1…100%, переход 0…30 секунд, только на поддерживающем устройстве `light`.

## 3. Объединение правил
- Активность устройства — логическое ИЛИ всех активных правил.
- Если несколько активных правил задают яркость, итоговая яркость — максимальная. При завершении самого яркого правила уменьшить яркость до следующего максимума без выключения устройства.
- Если активные правила не задают яркость, включать устройство без указания яркости (сохранять её по возможностям устройства).
- При отсутствии активных правил у управляемого устройства — выключено.

## 4. Ручной приоритет
- Внешнее включение, выключение либо изменение яркости должно блокировать автоматику для этого устройства.
- Блокировка действует до ближайшего **реального изменения набора активных правил**, либо до явно заданного таймера (если он наступит раньше).
- Изменение датчика движения само по себе не завершает блокировку, пока не изменило фактическую активность правила.
- Собственные команды интеграции не должны ошибочно распознаваться как ручное управление.
- После снятия блокировки восстановить расчётный автоматический режим.

## 5. Сохранение и перезапуск
- Правила, ручные режимы, время их истечения и последняя активность сохраняются в хранилище Home Assistant.
- После перезапуска актуальные расписания и текущие состояния датчиков переоцениваются. Изменившаяся за время остановки активность правил может завершить сохранённый ручной режим.
- Недоступные устройства не должны получать команды.

## 6. Примеры приёмки

| ID | Условия | Ожидаемое поведение |
|---|---|---|
| LM-001 | Каждый день: закат +10 мин → 23:00 | Включить вечером; если начало не раньше 23:00, пропустить |
| LM-002 | 23:00 → восход: движение | Свет 25%, выключение через 5 минут без движения |
| LM-003 | Ручное ON/OFF/яркость | Сохранить до следующего реального изменения правила или таймера |
| LM-004 | Пн–пт, 19:00, 2 часа | Включить на 60%, завершить в 21:00 |
| LM-005 | Правила 30% и 80% | Установить 80%, после окончания второго — 30% |

## 7. Интерфейс
- UI для просмотра устройств, правил, статусов, ручных блокировок, яркости.
- CRUD для независимых правил, настройка задержки без движения, расписаний, дней недели, яркости.
- Сервер Python, хранилище, Config Flow; панель Lovelace.
- HACS — целевая модель распространения, отдельно от обычного развёртывания из монорепозитория.

## 8. Реализованный объём прототипа v0.1
Модель правил, периодический пересчёт, реагирование на датчики, сохранение, сервисы `turn_on`/`turn_off`, административная WebSocket API, начальная карточка с JSON-редактором и независимые unit-тесты модели. Полноценный визуальный редактор, журнал действий, матрица совместимости оборудования и HACS-пакетирование — последующие этапы. До натурных тестов нельзя считать реализацию принятой.
